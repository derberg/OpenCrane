# MCP Server Auth: Standard OAuth (self-hosted or external IdP) + scope-based content authorization

**Status:** Design (revised) — pending user review, then implementation plan
**Date:** 2026-07-01

> **Supersedes** the first revision of this spec (hand-rolled HTTP Basic middleware + custom `Principal`/contextvar). That approach is dropped: it was not MCP-spec-compliant and would not trigger MCP clients' built-in authorization flow. This revision builds on the MCP Python SDK's auth framework instead.

## Problem

The MCP server generated by OpenCrane is typically **hosted** (Streamable HTTP, via Docker). When a consumer adds a hosted MCP server to their agent framework, the standard, friction-free experience is: the client detects it's unauthorized, kicks off authorization, a browser opens, the consumer approves/enters a credential once, and the client stores the resulting token. OpenCrane currently has **no auth at all**.

Two needs:

1. **Consumer-simple authentication** that triggers the MCP client's standard browser authorization flow — with *or without* an external identity provider.
2. **Fine-grained content authorization**: a caller's token *scopes* determine which documentation *sources* they may retrieve.

## Key finding: MCP authorization is OAuth-only, and the SDK provides the machinery

Per the MCP Authorization spec (revisions 2025-06-18 and current 2025-11-25), the **only** standardized interactive auth scheme is **OAuth 2.1** (`Bearer`). There is no HTTP Basic auth in the spec, and clients have no standardized username/password prompt. Therefore, to get the "browser opens, click authorize" experience, the mechanism must be OAuth.

The MCP Python SDK (`mcp==1.28.1`, via `FastMCP`) supplies both sides:
- **External-IdP / resource-server mode:** pass a `token_verifier`; the SDK serves the RFC 9728 Protected Resource Metadata, emits the `401 + WWW-Authenticate: Bearer resource_metadata=…` challenge, validates bearer tokens, and exposes the token to tools via `get_access_token()`.
- **Self-hosted authorization-server mode:** pass an `auth_server_provider` (an `OAuthAuthorizationServerProvider`); the SDK mounts `/authorize`, `/token`, `/register`, and AS metadata, and derives a token verifier automatically. A custom (unauthenticated) route serves a browser **login form**. This is the [OpenCollective MCP](https://github.com/…/opencollective-mcp) pattern: the consumer opens a form, pastes a credential, and it becomes their access token — no external IdP.

This lets OpenCrane deliver the exact UX the maintainer wants for **both** the "I have a Keycloak" case and the "I just want a simple hosted server with a login" case.

## Goals

- **`local` mode** — OpenCrane acts as its own OAuth 2.1 authorization server. The MCP client opens OpenCrane's browser login form; the consumer authenticates with an operator-configured **one-time token** or **username/password**; that mints the access token. No external IdP; no env vars for the consumer.
- **`oauth` mode** — OpenCrane is an OAuth resource server delegating to an external IdP (Keycloak/Auth0/Entra); serves discovery metadata; validates audience-bound bearer JWTs.
- **`none` mode** — default; unauthenticated (current behavior). Always the mode for stdio.
- **Layer 2 authorization** — declarative `scope → [source_name,…]` mapping, enforced by constraining the `source_names` filter on both Milvus and BM25 search (narrow-only; empty ⇒ zero results).
- Migrate the **HTTP transport to FastMCP**, preserving OpenCrane's existing tools (dynamic schemas + conditional tools) and their `(arguments: dict) -> list[TextContent]` handlers **unchanged**.
- Fail-closed on misconfiguration; secrets from env only; 100% test coverage; stdio behavior unchanged.

## Non-Goals

- OpenCrane as a full multi-tenant identity provider (user database, password reset, consent screens beyond a minimal form). `local` mode is a lightweight AS: a single operator-configured credential gate.
- Per-chunk/topic tagging. Authorization gates at the **source** level (`source_name`), already indexed and filterable — no schema change or reindex.
- OAuth on stdio (spec says stdio uses environment credentials; unchanged).
- Refresh tokens in `local` mode (the SDK provider can decline them; clients re-run the short browser flow).

## Architecture

```
                     ┌── stdio transport ── no auth (env creds), unchanged
serve --transport ───┤
                     └── http transport (FastMCP) ──┐
                                                     │
   auth.type:  none            oauth                 local
               (open)   (resource server,       (self-hosted AS:
                          token_verifier,         auth_server_provider
                          discovery→IdP)          + /login form)
                                     │                    │
                                     └──── bearer token ──┘
                                              │  scopes on AccessToken (get_access_token())
                                              ▼
                        Layer 2: scope_sources → allowed source_names
                                              │  (union over scopes; ∩ client source_names; empty ⇒ no results)
                                              ▼
                        search: AND allowed source_names into Milvus + BM25
```

### HTTP transport on FastMCP

`opencrane/mcp/http_server.py` is rebuilt around `FastMCP`:
- Construct `FastMCP("opencrane", stateless_http=True, json_response=False, lifespan=…, <auth wiring>)`.
- Register OpenCrane's existing tools onto FastMCP via a small **bridge** that preserves today's exact wire behavior (see below).
- Serve `app = mcp.streamable_http_app()`; re-add the `/health` liveness probe as an unauthenticated `@mcp.custom_route`.
- `init_services()` runs in the FastMCP `lifespan`.
- `streamable_http_path` set so the advertised MCP endpoint matches what the CLI prints (consolidate the current `/http` + `/mcp` dual route).

**Tool bridge (preserves dynamic + conditional tools, reuses handlers verbatim).** FastMCP's decorator path derives schemas from function signatures, which cannot express OpenCrane's runtime-built enums. Instead, register hand-built `Tool` objects directly:

```python
from mcp.server.fastmcp.tools.base import Tool
from mcp.server.fastmcp.utilities.func_metadata import FuncMetadata, ArgModelBase
from pydantic import ConfigDict

class _PassthroughArgModel(ArgModelBase):
    model_config = ConfigDict(extra="allow")
    def model_dump_one_level(self):
        return {"arguments": dict(self.__pydantic_extra__ or {})}

def _register(mcp, name, description, input_schema, handler):
    mcp._tool_manager._tools[name] = Tool(
        fn=handler, name=name, title=None, description=description,
        parameters=input_schema,                                   # today's exact JSON schema
        fn_metadata=FuncMetadata(arg_model=_PassthroughArgModel),  # keeps output_schema=None
        is_async=True, context_kwarg=None, annotations=None,
    )
```

The existing `_build_search_tool()` schema builder, the conditional `_has_yaml_chunks()` / `_has_list_item_chunks()` gates, and the handlers (`search_docs`, `health_check`, `get_yaml_definition`, `get_metadata_schema`, `get_list_members`) are reused unchanged — only *where* they are registered moves. Because the tool conditions depend only on indexed data (fixed for process lifetime), evaluating them once at startup equals current behavior.

**Risk & mitigation:** the bridge uses semi-private SDK internals (`mcp._tool_manager._tools`, `ArgModelBase`). Mitigation: pin `mcp==1.28.*`, and add a **smoke test** asserting `mcp.list_tools()` advertises the expected tool names + `inputSchema` (so an SDK bump can't silently regress the wire contract).

### Layer 1 · Authentication modes (config-selected)

`auth.type` in `config.yaml`:

| type | SDK wiring | Consumer experience | Deps |
|------|-----------|---------------------|------|
| `none` (default) | no auth | open | none |
| `local` | `auth_server_provider=OpenCraneAuthProvider(...)` + `AuthSettings(issuer_url=PUBLIC_URL, client_registration_options=enabled)` + `/login` custom route | client opens OpenCrane's login form; consumer pastes a token or enters user/pass; token minted & stored by client | none extra |
| `oauth` | `token_verifier=JwtTokenVerifier(...)` + `AuthSettings(issuer_url=IdP, resource_server_url=PUBLIC_URL, required_scopes=…)` | client discovers IdP, browser → IdP login, token stored | `opencrane[auth]` (PyJWT) |
| `custom` | operator supplies `token_verifier` or `auth_provider` on `OpenCraneConfig` | as implemented | operator-defined |

**`local` mode — `OpenCraneAuthProvider`** (subclass of `OAuthAuthorizationServerProvider`, modeled on OpenCollective's `OCAuthProvider`):
- `authorize()` stores a pending request and redirects to `/login?request_id=…`.
- `/login` (unauthenticated custom route) renders an HTML form and, on POST, calls `complete_login()`.
- Credential check (operator-configured, from **env**):
  - **token mode** — `OPENCRANE_ACCESS_TOKEN` (one or more, comma-separated). The form takes a pasted token; accepted iff it matches (constant-time).
  - **password mode** — `OPENCRANE_LOGIN_USER` / `OPENCRANE_LOGIN_PASS`. The form takes user+password.
  - Which form is shown is chosen by `auth.local.method: token | password` (default `token`).
- On success: mint a single-use authorization code (short TTL) → exchanged for an **access token**. The access token is a random opaque string; the provider validates it presence-only against an in-memory store that also carries the granted **scopes** (`auth.local.scopes`, default: empty ⇒ AllowAll = all sources). In-memory is acceptable: on restart/replica-miss the client simply re-runs the short browser flow (matches the OpenCollective design).
- `PUBLIC_URL` env var (the server's public https URL) is the OAuth issuer; **must be https in production** (OAuth 2.1 requirement, enforced/allowed-localhost by the SDK).

**`oauth` mode — `JwtTokenVerifier`** (implements the SDK `TokenVerifier`: `async def verify_token(token) -> AccessToken | None`):
- Validate the JWT via the IdP's JWKS (discovered from `issuer`): signature, `iss`, `exp`, and **audience binding** (`aud` must include this resource — RFC 8707/9068; reject otherwise).
- Return `AccessToken(token=…, client_id=…, scopes=<from scope_claim>, …)`; invalid → `None` (SDK emits 401). Lazy-import PyJWT; absent `[auth]` extra ⇒ clear `AuthConfigError`.

### Layer 2 · Authorization (content scoping) — unchanged from prior revision

Declarative in `config.yaml`:
```yaml
auth:
  type: oauth            # or local
  oidc: { issuer: https://idp/realms/docs, audience: opencrane-docs, scope_claim: scope }   # oauth only
  scope_sources:
    "docs:public":   [cennso-glossary]
    "docs:internal": [cgw, tsr, tposs]
  default_sources: [cennso-glossary]
```
- Read the caller's scopes from `get_access_token().scopes` at search time.
- `allowed = union(scope_sources[s] for s in scopes)`; no match ⇒ `default_sources`.
- Intersect with any client-supplied `source_names` (narrow-only). Empty `⇒` **short-circuit to no results** (never pass `[]` to a backend — falsy `[]` disables the filter and would leak all sources).
- No `scope_sources` configured ⇒ allow all (authenticated = full access; the `local`/gate case).
- Enforcement point: `_search_documentation_impl`, constraining the single `source_names` local that both semantic and keyword backends read.

### Config parsing & fail-closed rules

`auth:` block parsed once at startup; each of these raises and refuses to boot:
- unknown `auth.type`;
- `oauth` without `oidc.issuer`/`oidc.audience`;
- `local` + `method: token` with no `OPENCRANE_ACCESS_TOKEN`; `method: password` with missing `OPENCRANE_LOGIN_USER`/`PASS`;
- `local`/`oauth` without `PUBLIC_URL` (needed as issuer);
- `scope_sources`/`default_sources` referencing an unknown configured source (when sources are known);
- `oauth` selected but `opencrane[auth]` not installed.

## Security

- OAuth 2.1 over HTTPS in production (`PUBLIC_URL` must be https; SDK allows http only for localhost).
- `oauth` mode enforces audience binding — reject tokens not minted for this resource (confused-deputy prevention); never forward the client token anywhere.
- `local` mode: credentials from env only; constant-time comparison; authorization codes single-use with short TTL; access tokens never written to disk; login-form output HTML-escaped (XSS boundary).
- Fail-closed on every misconfiguration; `serve` logs the active auth mode (never secrets).
- Layer-2 enforcement is server-side; the client `source_names` param is a narrowing convenience only.

## Testing (100% coverage)

- **Config parsing:** all fail-closed rules; happy paths for `none`/`local`/`oauth`.
- **Policies:** union, default fallback, narrow-only intersection, empty allowlist.
- **`local` provider:** `authorize` → pending; form render (HTML-escaped); `complete_login` valid token/user-pass → code; invalid → error; code single-use + TTL; access-token presence check carries scopes; token & password methods; missing-env fail-closed.
- **`oauth` verifier:** valid RS256 token (mint with a test key, inject signing-key resolver); bad audience/issuer/expiry → `None`/401; scope claim string vs list; missing `[auth]` → `AuthConfigError`.
- **FastMCP app:** smoke test that `mcp.list_tools()` advertises expected names + `inputSchema` (guards the private-API bridge); a tool call through the app returns `list[TextContent]` unchanged; conditional tools appear only when their chunk types are indexed; `/health` open; unauthorized MCP request → 401 with `WWW-Authenticate` (via `TestClient`, no real IdP).
- **Layer-2 enforcement:** allow-all passes through; scope policy constrains sources into the backend; empty allowlist short-circuits without hitting the backend (no leak); custom deny.
- **stdio:** unchanged (no auth) — existing tests must stay green.

## Maintainer experience (target: `ai-docs/.opencrane`)

**`local` (no IdP, browser login) — config + env, no Python:**
```yaml
# config.yaml
auth:
  type: local
  local: { method: token }     # or: password
```
```yaml
# docker-compose.yml
    environment:
      PUBLIC_URL: https://docs-mcp.example.com
      OPENCRANE_ACCESS_TOKEN: ${OPENCRANE_ACCESS_TOKEN:?set me}   # method: token
      # OR, for method: password —
      # OPENCRANE_LOGIN_USER / OPENCRANE_LOGIN_PASS
```
Consumer: `claude mcp add --transport http docs https://docs-mcp.example.com/mcp` → client prompts to authorize → browser opens OpenCrane's login form → paste the token (or enter user/pass) → done.

**`oauth` (external IdP, scope-gated) — config + env + `[auth]` extra:**
```yaml
auth:
  type: oauth
  oidc: { issuer: https://login.example.com/realms/docs, audience: opencrane-docs, scope_claim: scope }
  scope_sources:
    "docs:public":   [cennso-glossary]
    "docs:internal": [cgw, tsr, tposs]
  default_sources: [cennso-glossary]
```
Dockerfile installs `opencrane[auth]`; `PUBLIC_URL` set. Consumer authorizes against the IdP in the browser; a token with only `docs:public` retrieves only `cennso-glossary`.

## Open questions / deferred

- Per-credential scope differentiation in `local` mode (multiple tokens → different scope sets). v1 grants one configured scope set to any successful login.
- Opaque-token IdPs (introspection, RFC 7662) in `oauth` mode — `custom` verifier covers it for now.
- Stateless `local` access tokens (signed JWT) for multi-replica without re-auth — deferred; in-memory presence check is the v1 (client re-auth is cheap).
- Collapsing the legacy `/http` vs `/mcp` route names — decide the single canonical path during implementation and update CLI help.
